# Issue #54: 分割OMR候補の結合検証（2026-09-23）

`Automatic.pdf`をAudiveris 5.11.0で処理すると、MusicXMLが2候補に分かれる。従来の画面ではどちらか一方だけをSongに保存していたため、原PDF全体を1曲として確認・保存できなかった。この記録は、候補の原譜上の位置を照合し、反復展開後のイベントを結合する検証結果を残す。原PDF、ページ画像、`.omr`、全曲MusicXML、全曲SongはGitに含めない。

## 原譜上の範囲

manifestと一致する原PDF SHA-256は`b927162911cfd804178baffac255d290251a8dc7b4c8e2a078c2184f5d2b052c`。Node.js 22.12.0、Poppler 26.09.0、Audiveris 5.11.0、300 DPI、ローカルPDF入力で`npm run omr:pdf`を実行した。ジョブIDは`omr-3c64bf54b45780de6eec`。実行時の一時パスなどがMusicXMLに含まれるため、候補SHA-256は再処理ごとに変わり得る。

| 候補 | 今回のMusicXML SHA-256 | PDF上の範囲 | 譜面小節 | 反復展開後 |
| --- | --- | --- | ---: | ---: |
| candidate-1 | `044653ff7cb4e30f5635d17700d81bb820b6b11ef7b0f5c54481c98fd39f3412` | 1ページ目・譜面領域1、2段 | 8 | 8 |
| candidate-2 | `ff9e75a3e355f59fa4b732b23c997dbd170fcd2a0bbae7fb9cb0d5da9e0be187` | **1ページ目・譜面領域2から**5ページ目 | 64 | 78 |

Audiverisの保存済みプロジェクトでは、PDFの**同じ1ページ目に2つの譜面領域**がある。候補2はPDF 2ページ目からではなく、候補1の下に続く1ページ目の10小節から始まる。候補2のMusicXML小節番号は1に戻るため、その番号だけでは並びを判定できない。ジョブの`sourceLayout`は物理的な譜面位置72件、各候補の`sourceMeasures`は8件と64件で、全72件が重複・欠落なく譜面順に対応した。

## 結合結果

各候補を個別の`ImportDraft`で確認したうえで、PDF上の譜面位置から順番を決め、反復展開済みの小節とコード・旋律を一曲へ移した。候補2の開始位置は結合Songのtick `15840`。8 + 78 = **86小節**、終端tick `166680`、コード60件、旋律450音となった。候補2の明示的な調・拍子・テンポ変更は候補1の終端tickを足して配置する。変更が候補2の先頭に存在しない場合は、候補1から有効な値を引き継ぐ。異なる候補のイベントIDとtie IDは衝突しないよう区別する。

位置メタデータがない旧ジョブ、候補未読込、PDF位置の重複・欠落、候補内の譜面順の逆転、tick解像度の不一致、候補境界をまたぐ反復または番括弧、結合後の小節数上限超過は結合を止め、候補名と分かる範囲のPDF位置を表示する。自動的に片方を捨てる経路はない。D.S.／Codaによる全曲演奏順の精度はissue #55の範囲で、今回の86小節が原譜の最終演奏順と一致するとは主張しない。

## 検証

- `src/domain/music/omrJobMerge.test.ts`の小さな2候補スコアで、同じPDFページ内の譜面領域順、反復後の小節と音符、調・拍子・テンポの境界tick、重複・欠落の停止を確認した。
- 実OMRジョブの両MusicXMLをハッシュ照合してパースし、結合計画の問題0件と86小節のSong生成を確認した。
- 開発用Chromeで原PDF、ジョブ、2候補を読み込み、候補2の小節1がPDF 1ページ目・譜面領域2に表示されることを確認した。順番と範囲を確認するチェックを入れ、1曲として端末の`localStorage`へ保存し、編集画面の小節数86を確認した。これは操作経路の検証であり、86小節の音高・調・テンポを校正したことを意味しない。公開環境やサーバーの楽曲データは変更していない。

再現には、空の`artifacts/`配下へ原PDFを再処理し、生成した`job.json`と候補2件を確認画面へ読み込む。候補SHA-256がこの記録と異なる場合は、同じジョブに記録された各SHA-256との一致を確認する。原PDFのハッシュ照合は`npm run benchmark:verify-sources`、コードの検証は`npm test`、`npm run lint`、`npm run build`で行う。
